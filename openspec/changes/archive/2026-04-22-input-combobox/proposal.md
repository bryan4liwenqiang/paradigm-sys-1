## Why

当前会话启动区与阶段交互区中的输入字段主要是纯文本输入，用户需要手动记忆可选值，输入成本高且容易出现不一致表达。将输入统一升级为“下拉选择 + 手动输入”双模式，可以同时提升录入效率与表达自由度，并减少无效澄清轮次。

## What Changes

- 将现有关键输入字段改造为“双模式输入组件”：可从预置选项中选择，也可手动输入自定义值。
- 为双模式输入建立统一的前端交互规则（切换模式、默认值、草稿保存、回填）。
- 调整会话启动请求与会话恢复展示，保证双模式字段在 API 层向后兼容。
- 补充输入值规范化策略，降低自由输入导致的上下文噪声。

## Capabilities

### New Capabilities

- `dual-mode-input-controls`: 定义下拉选择与手动输入共存的输入控件行为规范与状态管理规则。
- `input-option-catalog`: 定义各输入字段的推荐选项目录与可扩展策略（包含兜底自定义输入）。

### Modified Capabilities

- `session-input-modeling`: 将会话输入建模从“文本为主”扩展为“选项+文本”混合模型，并明确兼容语义。
- `session-workflow-engine`: 调整输入消费与缺口识别逻辑，使标准化选项值与自定义值都可被稳定处理。

## Impact

- `standalone/web/index.html`: 输入区组件结构变更（下拉与手动输入切换）。
- `standalone/web/app.js`: 输入状态管理、模式切换、草稿持久化与请求组装逻辑。
- `standalone/MappingServer.java`: 会话创建参数解析与规范化处理，保持现有字段兼容。
- API 影响：请求/响应以“新增可选字段”为主，保持向后兼容，不移除既有字段。

### Non-goals

- 不在本次变更中引入复杂词典服务或远程配置中心。
- 不在本次变更中重构推荐引擎评分模型。
- 不在本次变更中统一改造 Spring 模式全部表单页面，仅先落地当前 standalone 主流程。
